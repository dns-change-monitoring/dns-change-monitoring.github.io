LOCAL DNS COMPARISON TOOL

Compare DNS record values

Runs in your browser

Paste the RDATA from two lookups of the same name and type, one value per line. For example, paste the IPv4 addresses from two A-record answers. This tool trims surrounding whitespace, removes duplicate lines and ignores line order. It preserves case, TXT content and trailing dots; it is not a full DNS parser.

No DNS queries or uploads are made. These text boxes are not saved between visits. Do not paste the whole dig response, TTL columns or mixed record types.

Compare the sample values to see additions and removals.

Read a DNS record diff correctly

The tool compares two sets of text values. It tells you which lines disappeared and which lines appeared. It does not perform DNS queries, verify the authoritative server or decide whether a change is expected. Use a successful lookup for the same owner name and record type on both sides.

Address replacement
Accepted 192.0.2.10, current 192.0.2.20: one removal and one addition. Verify the deployment rather than assuming that a resolving address is the correct address.
Multiple values, different order
Two addresses in reverse order are the same set. The “Try a reordered answer” button demonstrates this case. Repeated identical lines are also ignored.
MX preference changed
10 mail.example.com. and 20 mail.example.com. differ. Keep the preference number with the target because the complete MX value matters.
TXT policy changed
Paste the complete value as presented, keeping its internal spaces and case. The tool preserves them. It does not reconstruct multiple quoted TXT character-strings or infer whether two differently formatted policies have equivalent meaning.
CNAME target formatting
service.example.net. and service.example.net are reported as different text. This tool deliberately does not implement DNS-name normalization. Inspect the record type and source before calling it a configuration change.
Empty current answer
The comparison is rejected. An empty text box could represent a missing RRset, a failed query or a copy-and-paste error. Check the status-bearing response first, then handle confirmed deletion as a separate monitoring event.

From a one-off comparison to DNS change monitoring

A browser diff is useful during an incident or migration. Ongoing monitoring additionally needs a polling schedule, stored accepted state, record-aware normalization, a failure policy and reliable delivery of DNS change alerts. Follow the authoritative lookup runbook to capture better inputs.

The false-positive guide explains which differences a production monitor should evaluate before notifying someone. DNS Notify’s hosted service implements its own comparison rules; this small local tool is intentionally narrower.
